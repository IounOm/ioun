# มาตรฐาน README และ Diagram

> กฎ (ชี้จาก `rules/delivery.md` § Change discipline) — ใช้ทุกครั้งที่**สร้างโปรเจกต์ใหม่** หรือ**แก้โค้ดจนต้องแก้ README**

## When to Update the README
- สร้างโปรเจกต์ใหม่ → มี README ตั้งแต่ commit แรกที่มีโค้ดจริง
- แก้โค้ดแล้วสิ่งเหล่านี้เปลี่ยน → แก้ README **ใน PR เดียวกัน**: วิธีติดตั้ง/รัน · การตั้งค่า (env/config) · API/route · feature ที่ผู้ใช้เห็น · โครงสร้างไฟล์ · การ deploy · แผนภาพการไหลของข้อมูล
- แก้ภายในที่ไม่กระทบสิ่งข้างบน (refactor, แก้บั๊ก) → ไม่ต้องแตะ README

## Language
- **ภาษาตามคนอ่าน:** repo ที่คนอ่านหลักเป็นทีมคนไทย (งานบริษัท · งานลูกค้า) → **ภาษาไทย** โดยศัพท์เทคนิค คำสั่ง ชื่อไฟล์ ชื่อตัวแปร คงเป็นภาษาอังกฤษ · repo สาธารณะหรือคนอ่านต่างชาติ → ภาษาอังกฤษ
- **ไม่ทำ 2 ภาษาคู่กัน** — ต้องดูแล 2 ชุด สุดท้ายจะมีชุดหนึ่งไม่ตรงกับปัจจุบัน
- `AGENTS.md` (คนอ่านคือ AI) ภาษาอังกฤษเสมอ
- หัวข้อ (`##`) จะไทยหรืออังกฤษก็ได้ แต่ใน repo เดียวกันให้เหมือนกันทั้งไฟล์

## README Structure
เรียงตามสิ่งที่คนรับโปรเจกต์ต่อต้องรู้ก่อน (ข้ามหัวข้อที่ไม่มีเนื้อหาได้):

1. **ชื่อ + 1 ย่อหน้า** — คืออะไร ของใคร ทำงานบนอะไร · งานลูกค้าใส่คำเตือน "ข้อมูลลับ ห้ามเผยแพร่"
2. **ภาพหน้าจอ** (ถ้ามี UI) — ไว้บนสุด คุ้มที่สุดสำหรับคนรับงานต่อ เก็บที่ `docs/`
3. **ตารางสรุป** — ลูกค้า/เจ้าของ · ผู้รับผิดชอบ · stack · เครื่องที่รัน
4. **Features** — สิ่งที่ผู้ใช้เห็นและทำได้จริง (ตรวจกับโค้ดก่อนเขียน อย่าเดาจากชื่อ id/ตัวแปร)
5. **การทำงาน** — แผนภาพ Mermaid + ตารางความถี่/เกณฑ์สำคัญ
6. **สิ่งที่ต้องมี → เริ่มใช้งาน** — คำสั่งที่ copy ไปรันได้เลย
7. **ใช้งานจริง / deploy** · **การตั้งค่า** (ตาราง key + ลำดับที่ระบบอ่านค่า)
8. **API** · **โครงสร้างโปรเจกต์** · **ไฟล์ที่ระบบสร้างเองตอนรัน** (ที่ git ignore)
9. **แก้ปัญหาเบื้องต้น** (ตาราง อาการ → สาเหตุ) · **ความปลอดภัย** · **สิ่งที่ยังขาด**
10. ลิงก์ไป `AGENTS.md` สำหรับ AI

## Diagram Tools
**ค่าเริ่มต้น = Mermaid** · ห้ามวาดแผนภาพด้วยตัวอักษร (ASCII art) — อ่านยากและล้นจอบน GitHub

| เครื่องมือ | เหมาะกับ | ใช้บน GitHub | ข้อดี / ข้อจำกัด |
| --- | --- | --- | --- |
| **Mermaid** ⭐ (ค่าเริ่มต้น) | การไหลของข้อมูล · ลำดับการทำงาน · สถาปัตยกรรม | **แสดงผลในตัว** ใช้ code block `mermaid` | เป็นข้อความ แก้ง่าย ดู diff ใน git ได้ AI แก้ให้ได้ · ปรับ layout ได้ไม่ละเอียด |
| **draw.io** (diagrams.net) | สถาปัตยกรรมที่ต้องวางตำแหน่งเป๊ะหรือใส่ไอคอนอุปกรณ์ (devices) | export `.drawio.svg` แล้วแปะเป็นรูป | ไฟล์ SVG นี้เปิดกลับมาแก้ใน draw.io ได้ · มี extension ใน VS Code ฟรี |
| **Excalidraw** | ภาพร่างลายมือ อธิบายภาพรวม | export `.svg` / `.png` | เร็ว อ่านง่าย · ไม่เหมาะกับภาพที่ต้องเป๊ะ |
| **D2** | แบบเดียวกับ Mermaid แต่ layout สวยกว่า | ต้องใช้ CLI สร้าง SVG แล้ว commit รูป | ต้องติดตั้งเพิ่มและสร้างรูปใหม่ทุกครั้งที่แก้ |
| **ScreenToGif / ShareX** (Windows ฟรี) | บันทึกหน้าจอเป็น GIF หรือคลิปสั้น | GIF แปะได้เลย · วิดีโอต้องลากไฟล์ใส่หน้าแก้ไขบนเว็บ GitHub | GIF ควร < ~5–10 MB เก็บที่ `docs/` |

### Mermaid Tips
- ใช้ `flowchart LR` สำหรับการไหลของข้อมูล · `subgraph` แบ่งกลุ่ม "แหล่งข้อมูล / server / หน้าจอ"
- ใส่ข้อความใน node และ edge ด้วยเครื่องหมายคำพูดเสมอ (`A["/api/x"]`, `-->|"ทุก 5 นาที"|`) — กันอักขระพิเศษและภาษาไทยทำ parse พัง · ขึ้นบรรทัดใหม่ใน node ด้วย `<br/>`
- ฐานข้อมูล/ไฟล์ log ใช้ `[( )]` (รูปทรงกระบอก)
- **ตรวจก่อน push:** parse ด้วย mermaid.js ใน browser (หรือเปิด preview ใน VS Code / หน้าแก้ไขของ GitHub) — repo private ดูผลบนเว็บต้อง login
